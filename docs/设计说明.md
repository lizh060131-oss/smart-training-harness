# 智训引擎 · 设计说明

> 面向第二届北京市大学生"人工智能+"创新大赛（工大赛）题目九「智训引擎」。
> 本文档描述 harness v2 的系统设计、核心方法与决策依据。

## 1. 问题定义与总体思路

题目要求构建一个**能自主训练工业模型的引擎（harness）**：数据按批次流入，引擎无人干预地完成
"读历史 → 诊断漂移 → 规划实验 → 训练并评估 → 门控决策（上线/回滚）→ 记录"的闭环。
评分对象是**续训后的工业模型**（官方 NumPy MLP 检查点），而非引擎本身；引擎借助 PyTRIO 大模型
读写代码、使用工具，但本地 CPU 训练不依赖大模型即可独立运行。

核心设计原则：

1. **工业模型即官方协议模型**——全部续训落在官方 `model.py`/`train.py` 定义的 NumPy MLP 检查点上，
   不改网络结构、不动输入维度、不换任务，严格遵守"显式权重迁移才允许改结构"的约束。
2. **漂移流是全批次的累积历史**——每批新数据只增不删，训练在"全部历史 + 当前批"上进行，
   引擎必须自适应地决定"用多少历史、怎样加权"来应对概念漂移与灾难性遗忘。
3. **门控是安全的最终闸门**——上线决策不仅看当前批提升，还要看**对历史数据的遗忘程度**，
   用独立的 replay 池做防遗忘校验，杜绝"在新数据上更好、在老数据上崩坏"的假提升。
4. **可复现、可记录、可解释**——所有事件落入结构化 `engine_log.jsonl`，并镜像到 SwanLab
   （记录对象 = 被训练的工业模型，须公开）。

## 2. 系统架构

```
main.py (CLI 入口)
   └─ RoundEngine.run()
        ├─ DriftMonitor  漂移诊断（PSI / 均值位移 / 类别分布 JS 散度）
        ├─ Planner       实验规划（规则基线 + LLM 顾问，逐任务可调超参）
        ├─ train_run     官方 train.py 续训（from-baseline / resume）
        ├─ eval_checkpoint 官方 model.py 前向评估（Macro-F1 / RMSE）
        ├─ Gate          门控决策（DEPLOY_NEW / KEEP / ROLLBACK）
        ├─ Recorder      engine_log.jsonl + summary.json（权威记录）
        └─ SwanLabMirror 云端 SwanLab 镜像（cloud，失败本地兜底）
```

数据流（每轮，round = 一个流入批次）：

1. 读入 `batchNN.jsonl`，按 `val_ratio=0.2` 分层留出**当批验证集**（永不复用、不入训练）；
2. 再从**训练部分**切 `replay_ratio=0.1` 入 **replay 池**（跨轮累积，永不训练）；
3. 对"历史训练集 + 当前批"做漂移诊断；
4. 评估**静态基线**（官方基线冻结）与**当前已采纳模型**在当批验证集上的指标；
5. Planner 产出 ≥3 个候选实验（不同数据策略/超参）；
6. 每个候选 `resume` 自已采纳检查点续训 → 在"当批验证集 + replay 池"上评估；
7. Gate 在候选集中挑出"当批显著更好 + 不遗忘历史"的最优者 → `DEPLOY_NEW`；
   无合格候选且已采纳模型在 replay 上严重退化 → `ROLLBACK` 回父检查点；否则 `KEEP`。

## 3. 漂移监测（DriftMonitor）

对每批流入数据计算三类信号，输出可读的诊断摘要：

| 信号 | 计算 | 意义 |
|------|------|------|
| 均值位移 `mean_shift` | 当前批特征均值 vs 历史特征均值（标准化单位） | 传感器响应漂移/工况变化 |
| PSI | 10 分箱分布漂移 | 输入分布整体迁移 |
| 类别分布 JS 散度（分类） | 标签先验漂移 | 类出现/消失、先验变化 |

诊断摘要会作为**实验规划与 LLM 顾问的输入**（例如：某批缺类别、某特征均值跳变 3σ、
标签先验剧烈变化），驱动"强调近期数据"的 drift_focus 策略。

## 4. 实验规划（Planner）

规则基线（无 LLM 时）每轮产出 3 组递进假设：

| 策略 | 数据 | 目的 |
|------|------|------|
| `full_hist` | 全历史 | 基线：新旧均衡 |
| `recent_double` | 历史数据加两份当前批 | 加速适应漂移 |
| `balanced`（分类）/ `low_lr_long`（回归） | 全历史 | 防弱类遗忘 / 低学习率平滑适应 |
| `drift_focus`（漂移剧烈时插入） | 历史数据加三份当前批 | 强化适应剧烈漂移 |

超参按任务在 `configs/{TASK}.json` 的 `tuning` 段覆盖。配置 PyTRiO 后，A 保留两个规则候选，
强漂移时优先保留 `drift_focus`，B/C 保留三个规则候选。大模型可补充一个不同配置的候选。
A 的 `compact_recent` 给历史数据设置样本上限并按类保留代表样本。C 保留全历史，规则候选的
批大小统一为 256，近期加权在历史数据上追加一份当前批。

Harness 通过 PyTRiO Chat Completions 运行两步工具协议。`read_context` 读取实际规则源码、漂移诊断和历史摘要。
`write_strategy` 将模型给出的 `experiment(...)` 声明写入本轮策略文件，固定解析器校验后转成续训参数。
工具权限限于指定材料和策略文件。模型代码只经 AST 白名单解释，运行目标仍是官方 MLP 的续训入口。
日志逐轮记录实际工具调用、读取的历史轮数、策略哈希、候选训练结果和最终决策。请求失败或候选不合格时走规则回退。

## 5. 门控决策（Gate）—— 两级安全闸门

门控是引擎的核心安全机制，分为两级：

**第一级 · 当批增益**：候选必须在当前批验证集上**显著优于已采纳模型**
（分类 `deploy_margin=0.003` 绝对 / 回归 `0.002` 相对）。

**第二级 · 防遗忘（replay 池）**：以**静态基线在 replay 池上的指标**为固定参照，
计算候选在 replay 上的退化量 `loss`：

- `loss ≤ soft_budget(0.08/0.10)` → 通过（历史不遗忘）；
- `loss > hard_budget(0.30/0.40)` → **灾难遗忘，直接拒绝**；
- 中间区间 → **边际豁免**：候选 replay ≥ 已采纳模型 replay（严格占优），
  或当批增益 ≥ 边际 replay 损失（净增益为正）才放行。

两级都通过的候选中选当批指标最优者 `DEPLOY_NEW`。无候选通过且当前模型在 replay 上越过
hard 预算时，使用当轮验证集与 replay 池复评父检查点。父检查点恢复到 hard 预算以内、
且当批指标未明显退化才执行 `ROLLBACK`，同时从采纳链移除被回滚的检查点。其他情况下执行 `KEEP`。

B 在可识别历史轴承时使用设备等权排序。当批相对增益权重为 55%，每根轴承按官方基线 RMSE
归一化后的历史增益均值权重为 45%。得分为正且通过原有当批和回放门控的候选才部署。

**设计动机**：固定参照（静态基线在 replay 的值）而非"逐轮与上一轮比较"，避免连续小退化
下永远无法部署的死锁；hard 预算做绝对下限，杜绝长期蠕变导致的灾难遗忘。

## 6. 续训协议合规

- 第一轮 `--from-baseline` 从平台基线检查点起步；后续轮 `--resume` 上一轮选定检查点，
  恢复权重 + Adam 矩 + 标准化统计量 + epoch；
- 每轮输出**新目录**（`checkpoint.npz` + `training.json` + `history.jsonl`）；
- 标准化/目标缩放沿用检查点冻结统计量，验证集与 replay 池不参与任何统计量拟合；
- 训练/验证/replay 三者的 id 严格互斥，重复样本换新 id 保持唯一；
- 回归预测还原原单位并截断非负；分类输出类别分数。

## 7. 资源效率

- 全程 NumPy MLP，无 GPU，`BASELINE_CPU_THREADS` 控制在 1–8；
- 逐轮增量累积历史，训练仅在必要的数据规模上进行；策略通过"数据窗口"（recent2/recent3）
  与全历史之间权衡，既应对漂移又控制 CPU 时间；
- 引擎本身无重量级依赖（Python 3.11 + NumPy + swanlab），镜像体积远小于 2GB 上限。

## 8. 记录与可追溯（SwanLab）

- `engine_log.jsonl`：权威事件流（run_start / diagnosis / plan / experiment / decision /
  baseline_replay / replay_holdout），每次运行截断重写；
- `summary.json`：逐轮决策表 + 最终 replay 指标 + LLM 使用标记；
- SwanLab 云端：项目 `smart-training-harness`，镜像每实验指标（exp/{name}/primary/replay/seconds）、
  每轮决策（round/*）、被采纳实验的逐 epoch 训练曲线（train/loss、train/val_primary）。
  云端不可用时本地兜底，保证记录不丢失。
