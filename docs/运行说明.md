# 智训引擎 · 运行说明

## 1. 环境要求

- Python 3.10–3.12（推荐 3.11）
- NumPy 1.26.4（官方协议版本；实测 2.5.x 亦兼容）
- swanlab 0.10.5（记录用，可选但建议安装）

```bash
pip install numpy==1.26.4 swanlab==0.10.5
```

## 2. 目录结构

```
harness_v2/
├── main.py            # 统一 CLI 入口
├── engine.py          # 轮次引擎（诊断/规划/训练/门控/记录/SwanLab）
├── configs/{A,B,C}.json   # 三任务配置（模型结构/超参/tuning）
├── baselines/         # 官方 model.py / data.py / train.py / predict.py
├── checkpoints/       # 官方三基线 {A,B,C}-baseline.npz（本地开发用，不进镜像）
├── requirements.txt
└── Dockerfile
```

数据目录（引擎按 `batchNN.jsonl` 通配读取、按批次号排序）：

```
data/gas_jsonl/batch01..10.jsonl        # 任务 A（气体，10 批）
data/bearing_jsonl/batch01..10.jsonl    # 任务 B（轴承 RUL，10 批）
data/cmapss_jsonl/batch01..10.jsonl     # 任务 C（发动机 RUL，10 批）
```

每行 JSONL 包含 `id`、`inputs`、`answer`、`meta`，分类 answer 为英文类别，回归为数值。
旧工作目录的批次曾包含独立公开验证样本。正式本地对照前，用以下命令构造隔离验证数据的流：

```powershell
python .\tools\build_development_streams.py --out .\data\development_streams
```

将 `--data` 指向输出根目录下的 `A`、`B` 或 `C`。这是本地模拟流，赛方评测仍应使用平台挂载的数据。

## 3. 运行

```bash
# 从项目根目录运行。任务 A 默认最多 10 轮，每轮一个流入批次
python 1/harness_v2/main.py --task A --data data/development_streams/A --out 1/runs_v2/gas

# 任务 B / C
python 1/harness_v2/main.py --task B --data data/development_streams/B --out 1/runs_v2/bearing
python 1/harness_v2/main.py --task C --data data/development_streams/C --out 1/runs_v2/cmapss

# 指定基线检查点与轮数
python 1/harness_v2/main.py --task C --data data/development_streams/C --out 1/runs_v2/cmapss \
    --baseline 1/harness_v2/checkpoints/C-baseline.npz --rounds 10
```

其它参数：`--val-ratio 0.2`（当批验证集比例）、`--replay-ratio 0.1`（防遗忘池比例）、
`--seed 42`、`--min-experiments 3`。

## 4. SwanLab 记录

```bash
export SWANLAB_MODE=cloud               # cloud（默认）/ local / disabled
export SWANLAB_PROJECT_NAME=smart-training-harness   # 注意是 *_NAME，不是 SWANLAB_PROJECT
export SWANLAB_WORKSPACE=lizh-131         # 目标 SwanLab 空间
export PYTHONUTF8=1                     # 避免 Windows GBK 控制台编码错误
python main.py --task A --data data/gas_jsonl --out 1/runs_v2/gas_cloud
```

登录凭证：首次 `swanlab login` 写入 `~/.swanlab/.netrc`，或设 `SWANLAB_API_KEY`。
项目地址：https://swanlab.cn/@lizh-131/smart-training-harness

容器实时记录需要运行环境可访问 SwanLab，并通过运行时密钥字段注入 `SWANLAB_API_KEY`。
如果平台只提供下载日志，可以在完整运行结束后用已登录的本机补传 `engine_log.jsonl`：

```powershell
python .\tools\sync_swanlab_run.py --workspace lizh-131 --run <运行目录> --name <实验名称>
```

补传记录包含漂移诊断、候选训练指标、逐轮决策和最终 replay 指标。如果运行目录保留候选的
`history.jsonl`，还会画出各轮候选的训练损失和验证指标曲线，横轴为本次续训的 epoch。
相同日志使用固定实验 ID。可通过 `--epochs-only` 只为已补传的实验追加 epoch 曲线。

## 5. LLM 顾问（可选）

```bash
export PETRIO_BASE_URL=...   # OpenAI 兼容 API
export PETRIO_API_KEY=...
export PETRIO_MODEL=...      # 千问 4B / 27B
```

本地真实接口联调（从项目根目录运行，交互输入模型 ID 和 API Key）：

```powershell
python .\tools\run_pytrio_smoke.py
```

如果 Windows Terminal 的 Python 密钥提示处粘贴不便，可先用 PowerShell 隐藏输入：

```powershell
& {
    $pytrioKey = Read-Host '粘贴 PyTRiO API Key' -AsSecureString
    $previousKey = $env:PETRIO_API_KEY
    try {
        $env:PETRIO_API_KEY = [System.Net.NetworkCredential]::new('', $pytrioKey).Password
        python .\tools\run_pytrio_smoke.py --model '替换为控制台复制的完整模型 ID'
    } finally {
        $env:PETRIO_API_KEY = $previousKey
        $pytrioKey.Dispose()
    }
}
```

脚本默认使用 `https://pytrio.com/api/openai/v1`，将 A 任务跑 4 轮，输出写入新的
`1/runs_v2/gas_pytrio_*` 目录。`engine_log.jsonl` 每条 `plan` 的 `source` 记录
`hybrid`（规则候选加一个 PyTRiO 候选）、`pytrio`（模型规划）或 `rules`（规则规划）。
`model_tool` 事件记录 `read_context` 和 `write_strategy`，生成的受限策略保存在 `out/policies/`。
回退原因记录在 `llm_error` 中。`summary.json` 的 `llm_rounds` 统计采用模型计划的轮数，
`llm_tool_rounds` 单独统计使用代码读写工具且采用模型候选的轮数。

## 6. Docker 镜像打包

在项目根目录使用 PowerShell 打包单个 Linux/amd64 镜像：

```powershell
docker buildx build --platform linux/amd64 --load --provenance=false --sbom=false -t smart-training-harness:competition-v3 .\1\harness_v2
docker image inspect --format '{{.Os}}/{{.Architecture}}' smart-training-harness:competition-v3
docker save --platform linux/amd64 -o .\smart-training-harness-competition-v3-linux-amd64.tar smart-training-harness:competition-v3
```

确认镜像架构输出 `linux/amd64`。平台「Harness 镜像」上传 `docker save` 生成的未压缩 `.tar`。
默认基础镜像拉取失败时，可在 `docker buildx build` 中传入可达的 `--build-arg BASE_IMAGE=...`。

容器本地联调时，平台或调用方通过运行时环境注入 `PETRIO_BASE_URL`、`PETRIO_MODEL`、
`PETRIO_API_KEY` 和 `SWANLAB_API_KEY`。本地示例中的挂载路径只用于复现容器入口：

```bash
docker run --rm --platform linux/amd64 \
  -e PETRIO_BASE_URL -e PETRIO_MODEL -e PETRIO_API_KEY -e SWANLAB_API_KEY \
  -v <data>:/data -v <out>:/out smart-training-harness:competition-v3 \
  --task A --data /data/rounds --baseline /data/checkpoint.npz --out /out
```

## 7. 输出与复现

- `out/summary.json`：逐轮决策表、最终 replay 指标、实验数、LLM 使用标记；
- `out/engine_log.jsonl`：权威事件流；
- `out/swanlog/`：SwanLab 本地运行数据；
- `out/roundNN-expM-name/`：每实验的新检查点目录（checkpoint.npz + training.json + history.jsonl）。

复现：固定 `--seed 42` 与相同批次文件即可完全复现决策序列。

B/C 的公开整设备验证需要另行运行。使用上面的隔离训练流时，可以评估第十轮检查点：

```powershell
python .\tools\evaluate_rul_holdout.py --task B --run <B运行目录> --round 10
python .\tools\evaluate_rul_holdout.py --task C --run <C运行目录> --round 10
```

输出包含总体和按设备统计的 RMSE。B 另列逐轴承结果，C 另列逐 FD 子集结果与公开集逐样本 PHM08 分数。
工具在验证设备出现在所选轮次或更早的流批次时会报错。旧日志路径变化时用 `--data-dir` 指向原始批次目录。
